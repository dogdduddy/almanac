# 문장이 날씨처럼 등장한다 — 시그니처 인터랙션

2026-09-16 작성. Shipaton 2026 Design 상(2순위)을 겨냥한 첫 인터랙션. 코드: `composeApp/.../WeatherEntrance.kt`, `App.kt` 의 `PassageWords`.

## 1. 왜 이것인가

과거 수상작을 역산하면 이 상은 예쁜 스크린샷이 아니라 **만졌을 때의 움직임**을 본다. 심사 영상에서
움직임이 안 보이면 심사 자체가 안 된다. 그런데 이 앱은 종이 위의 문장이 전부다.

배경에 날씨 애니메이션을 깔고 글을 얹으면 글은 여전히 정지해 있다. 그래서 반대로 한다 —
**문장 자체가 날씨처럼 행동한다.** 배경은 종이 그대로. 파티클도 소리도 온보딩도 없다.

| 날씨 | 단어의 행동 | 길이 |
|---|---|---|
| 맑음 | 살짝 떠올라 놓인다. 읽기 순서대로, 빠르고 선명하게 | 850ms |
| 흐림 | 거의 움직이지 않고 천천히 배어 나온다 | 1500ms |
| 안개 | 흐림(blur 9dp)에서 한 덩어리로 초점이 맞는다 | 1700ms |
| 이슬비 | 작은 낙하, 위에서 아래로, 조금 흩어진 순서 | 950ms |
| 비 | 가속하며 떨어져 바닥에서 멈춘다(easeIn). 방울마다 조금씩 다르게 | 1150ms |
| 눈 | 천천히 내려앉으며 좌우로 한 번 흔들린다. 가장 느리다 | 2300ms |
| 뇌우 | 종이 전체가 두 번 번쩍인 뒤 세 무리가 **툭** 놓인다. 이징 없음 | 950ms |
| 바람 | 왼쪽에서 불려 와 살짝 지나쳤다가 제자리. 기울었다가 선다 | 1050ms |

## 2. 구조

- **페이지당 시계 하나.** `rememberWeatherEntrance()` 가 0→1 `Animatable` 을 만들고, 히어로·단어·보조 정보·섬광이
  전부 같은 값을 읽는다. 값은 graphicsLayer 람다 안에서 읽어 프레임마다 재구성되지 않는다.
- **단어 단위 레이아웃.** 하나의 Text 로는 단어를 따로 못 움직여 `FlowRow` + 단어별 Text. 띄어쓰기 폭은
  실제 공백 글리프를 잰다. 행 높이는 `LineHeightStyle.Trim.None` 이어야 28dp 가 유지된다 — 기본 트리밍이
  한 줄짜리 Text 의 위아래를 잘라 22dp 로 줄어든다.
- **낙하 거리는 줄 높이 안.** 비·눈·이슬비가 28dp 보다 멀리서 떨어지면 윗줄과 겹쳐 중간 프레임이 뒤죽박죽이 된다.
- **바람은 이웃 단어가 같은 위상.** 무작위로 흩으면 앞 단어 자리로 뒷 단어가 들어와 글자가 뭉친다.
  돌풍의 불규칙함은 인덱스의 사인 함수(주기 25단어)로만 준다.
- **안개의 blur 는 컨테이너 한 층.** 단어마다 걸면 레이어 경계에서 잘린다. Android 12 미만은 renderEffect 가
  무시되어 알파 페이드만 남는다 — 의도된 열화.
- **무작위는 결정적.** `jitter(index)` 는 정수 해시라 세 플랫폼에서 같은 순서로 떨어진다.
- **등장은 페이지가 자리 잡았을 때.** `pagerState.settledPage == index`. 미리 그려지는 옆 페이지에서
  시계가 돌아버리면 넘겼을 때 이미 끝나 있다. 문장의 정체(날짜·시간대·날씨·작품)가 바뀌면 다시 등장한다.
- **첫 화면 → 문장은 Crossfade 350ms.** 로딩 화면(제목)은 App Review 반려 대응으로 남긴다. 날씨가 캐시돼
  있으면 로딩 화면 없이 바로 문장이 조립된다.

## 3. 튜닝 도구 — 프레임 시트

`:desktopApp:test` 의 `EntranceFramesRenderTest` 가 창 없이 `ImageComposeScene` 으로 여덟 날씨 × 여섯 순간을
한 장(`build/reports/render/entrance-sheet.png`)에 뽑는다. 폰 빌드 없이 궤적을 비교한다.

**함정:** 오프스크린 렌더는 상태를 바꾼 render 호출이 아니라 **다음 호출**에서 픽셀이 나온다
(graphicsLayer 람다가 무효화만 되고 다음 프레임에 그려진다). 순간마다 같은 시각으로 두 번 그려야 한다.
한 번만 그리면 모든 프레임이 한 순간씩 늦게 보이고 t=1 이 아직 움직이는 중으로 찍힌다.
테스트는 t=1 프레임을 3배 길이 뒤의 정지 화면과 비교해 이걸 잡는다.
