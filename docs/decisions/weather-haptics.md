# 날씨별 햅틱 — 등장과 같은 타임라인

2026-09-16 작성. `weather-entrance.md` 의 3단계. 코드: `composeApp/.../Haptics.kt`(모델·파형 변환),
`WeatherEntrance.kt` 의 `entranceHaptics()`(패턴), `Haptics.android.kt` / `Haptics.ios.kt` / `Haptics.jvm.kt`(expect/actual).

## 1. 규칙 하나

**화면에서 무언가 놓이는 순간에만 진동한다.** 단어의 착지, 섬광의 정점, 돌풍의 지나감.
패턴은 등장 애니메이션과 같은 `windowFor()` 를 읽어 만들어지므로, 비의 방울이 놓이는 프레임에
진동이 온다. 화면과 무관한 진동은 없다. 눈으로 보는 것과 손으로 느끼는 것이 같은 사건이다.

| 날씨 | 진동 | 
|---|---|
| 맑음 | 히어로가 놓일 때 한 번, 선명하게 (0.5 / 0.8) |
| 흐림 | 없음. 조용한 날씨는 조용하다 |
| 안개 | 초점이 맞는 끝에 아주 부드럽게 한 번 (0.25 / 0.15) |
| 이슬비 | 네 단어마다 가볍게 스침 (0.22~0.34), 최대 10 |
| 비 | 히어로 0.55 + 세 단어마다 두드림 (0.3~0.6), 최대 16 |
| 눈 | 여섯 단어마다 45ms 눌러앉음 (0.14~0.22), 최대 8 |
| 뇌우 | 섬광 정점에 천둥 110ms(1.0)·70ms(0.55), 세 무리 착지에 딱딱딱 (0.4 / 0.9) |
| 바람 | 0.08~0.85 구간을 여섯 조각으로 낮게 울림, 0.15→0.45→0.15 |
| 종이 넘김 | 마른 소리 한 번 (0.5 / 0.9) |

괄호는 (intensity / sharpness). 세기는 실기에서 손으로 잡아야 한다 — 이 문서의 값은 첫 추정치다.

## 2. 모델은 CoreHaptics 어휘

`HapticEvent(atMs, durationMs, intensity, sharpness, transient)`. 세 플랫폼 중 표현력이 가장 큰 쪽에
맞춰야 나머지가 근사할 수 있다.
- **iOS**: 1:1. `CHHapticEngine` + `CHHapticPattern`. 엔진을 못 만들면(시뮬레이터 등) `UIImpactFeedbackGenerator` 로 첫 이벤트만.
- **Android**: `VibrationEffect.createWaveform(timings, amplitudes)` 한 개로 패턴 전체. transient 는
  sharpness 에 따라 12~32ms 펄스. 진폭 제어가 없는 기기는 켜고 끄기만 남는다. 기기 프리미티브(THUD 등)는
  더 좋지만 지원이 갈리고 한 번에 10개라 쓰지 않았다. `toWaveform()` 은 테스트로 고정.
- **데스크톱**: `NoHaptics`.

## 3. 모든 진동을 `USAGE_MEDIA` 로 보낸다

종이 넘김은 손가락이 만든 진동이지만 터치 피드백으로 보내지 **않는다.**

**근거:** 이 앱의 진동은 버튼을 눌렀다는 UI 신호가 아니라 등장 애니메이션과 한 몸인 콘텐츠다.
One UI 는 터치 피드백이 기본으로 꺼져 있어(`haptic_feedback_enabled=0`, 실기에서 확인),
종이 넘김만 거기 묶으면 문장이 놓이는 것은 느껴지는데 넘김만 조용해져 햅틱 언어가 반쪽이 된다.

**대가:** 터치 진동을 끈 유저도 페이지를 넘기면 진동을 느낀다. 미디어 진동 설정은 그대로
따르므로 진동 자체를 원치 않는 유저의 선택은 존중된다.

## 4. 실기에서 배운 것 (Galaxy S23, One UI)

- **VIBRATE 권한이 없으면 `vibrate()` 가 SecurityException 을 던진다.** runCatching 이 삼켜 조용히 아무 일도
  없다. `dumpsys vibrator_manager` 에 앱 기록이 하나도 없으면 이것부터 의심할 것.
- **usage 가 곧 어느 시스템 설정을 따르느냐다.** `USAGE_TOUCH` 로 보낸 진동은 터치 피드백이 꺼진 기기에서
  `ignored_for_settings` 로 버려진다. 3절의 결정이 여기서 나왔다.
- **무음 모드에서도 미디어 진동은 울린다.** 처음 실기가 조용했던 데에는 기기가 무음 모드였던 것도 겹쳤다.
- **스토어 배포본 위에 개발 빌드를 못 얹는다.** Play 앱 서명 키와 로컬 키가 달라 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`.
  실기 테스트는 스토어 빌드를 지우거나(그 기기의 아카이브가 사라진다) 내부 테스트 트랙으로 올려야 한다.
- 검증은 `adb shell dumpsys vibrator_manager | grep <package>` 로 한다. 에뮬레이터의 가상 진동기도 기록을 남긴다:
  `usage: MEDIA | played: [Step=382ms(amplitude=0.00),Step=16ms(amplitude=0.50)]` — 맑음 패턴 그대로.

## 5. 실기 검증 결과 (2026-09-16, Galaxy S23)

스토어 빌드를 지우고 개발 빌드를 올려 확인했다. 아카이브는 `run-as` 로 `user.db` 를 꺼내
과거 슬롯 5개(비·눈·뇌우·바람·안개)를 심어 만들었다.

넘길 때마다 **짧은 넘김 펄스 뒤에 그 페이지의 날씨 햅틱**이 이어진다:

| 넘긴 페이지 | 넘김 | 이어진 등장 햅틱 |
|---|---|---|
| 비 | 45ms | 759ms |
| 눈 | 44ms | 1858ms |
| 뇌우 | 41ms | 656ms |
| 바람 | 46ms | 1009ms |
| 안개 | 41ms | 1647ms |

빠르게 연속으로 넘기면 새 페이지의 `vibrate()` 가 이전 패턴을 끊는다 — 보고 있는 페이지의
연출만 남으므로 의도한 대로다.

## 6. 남은 것

- **세기는 아직 첫 추정치다.** 실기에서 손으로 잡아야 한다. 조정 지점은 `entranceHaptics()` 하나.
- iOS 는 컴파일만 확인. 실기 iPhone 에서 CoreHaptics 재생 확인 필요.
- 유저 설정(앱 안에서 끄기)은 없다. 시스템 미디어 진동 설정을 따르는 것으로 충분하다고 봤다.
