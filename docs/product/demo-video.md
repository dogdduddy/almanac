# 데모 영상 — 콘티와 촬영 준비

2026-09-23. Shipaton 제출용. 목표 길이 **1분 45초** (상한 2분에서 15초 여유).
외부 피드백 1차 반영본.

대사(내레이션)는 넣지 않는다. **영어 자막 8줄뿐이다.**
심사위원이 무음으로 볼 가능성이 높고, 대사가 적을수록 타이포그래피가 화면을 쥔다.

**심사 영상이지 브랜드 필름이 아니다.** 감성 훅으로 열되,
*무엇을 하는 앱인지*는 **14초 안에** 끝내고, KMP 와 결제 증명에 뒤 40초를 쓴다.

## 0. 먼저 알아야 할 제약

코드에서 확인한 것들이다. 넷 다 **콘티를 바꾼다.**

### 일본어 화면은 지금 찍을 수 없다

- `content.db` 의 엔트리는 **428편 전부 영어**다. 일본어는 0편이다
  (`SELECT language, COUNT(*) FROM entries GROUP BY language` → `('en', 428)`)
- 앱에 언어 선택이 없다. `AlmanacService.pages(language = "en")` 이 기본값 그대로 쓰인다.
  UI 문자열도 App.kt 에 영어로 박혀 있다

로컬라이제이션 컷은 **뺐다.** 찍으려면 아오조라 큐레이션 + 언어 선택 UI 가 먼저다.
남는 8초는 위젯 컷과 구매 컷에 돌린다.

> 같은 이유로 About 화면의 *"Japanese passages come from Aozora Bunko"* 는
> 지금 앱이 뒷받침하지 못하는 문장이다. 출처 **정책**을 적은 것이라 거짓은 아니지만,
> 심사위원이 찾아보면 안 나온다. 영상과 별개로 손볼지 결정할 것.

### 위젯도 아카이브도 유료가 아니다

**파는 것은 기능이 아니라 서가의 크기다.** 무료 유저도 위젯과 아카이브를 포함해
앱 전체를 쓴다. 다만 문장이 86편이라 같은 것을 다시 만나게 된다 (전체는 428편).

그래서 `Unlock widgets and the archive` 같은 자막은 **사실이 아니고**,
"잠긴 아카이브 → 해제" 그림도 만들 수 없다. 구매 컷은 아래 #8 처럼 짠다.

### 구매해도 지금 보고 있는 문장은 바뀌지 않는다

슬롯은 (날짜, 시간대, 위치)로 한 번 고정되면 보유 팩이 늘어도 다시 고르지 않는다
(결정론 계약 2.5 — 표시 안정성이 우선이다). **"구매 → 화면의 문장이 바뀐다" 는 못 찍는다.**
구매 뒤 눈에 보이게 변하는 것은 **서가 진입점(`The shelf`)이 사라지는 것**뿐이다.

### 문장 등장 애니메이션이 있다 — 이게 몽타주의 주인공이다

`WeatherEntrance.kt` 가 **문장 자체를 날씨처럼 움직인다.** 배경 파티클이 아니라 단어가
움직이는 것이라, 정지 스크린샷으로는 안 보이고 영상으로만 보인다 — 디자인 심사가 볼 것이 이것이다.

| 날씨 | 단어의 행동 | 길이 |
|---|---|---|
| 맑음 | 살짝 떠올라 놓인다 | 850ms |
| 흐림 | 거의 안 움직이고 천천히 배어 나온다 | 1500ms |
| 안개 | 흐림에서 한 덩어리로 초점이 맞는다 | 1700ms |
| 이슬비 | 작은 낙하, 조금 흩어진 순서 | 950ms |
| 비 | 가속하며 떨어져 바닥에서 멈춘다 | 1150ms |
| 눈 | 천천히 내려앉으며 좌우로 흔들린다. **가장 느리다** | 2300ms |
| 뇌우 | 종이가 두 번 번쩍인 뒤 세 무리가 툭 놓인다 | 950ms |
| 바람 | 왼쪽에서 불려 와 지나쳤다가 제자리 | 1050ms |

**촬영 메뉴에서 날씨를 바꾸면 등장이 다시 재생된다** (등장의 키에 날씨 그룹이 들어 있다).
몽타주는 이걸 그대로 쓰면 된다 — 컷마다 날씨를 바꾸는 것이 곧 애니메이션 재생이다.

컷 길이를 애니메이션보다 짧게 잡으면 안 된다. **눈은 2.3초짜리라 3초 컷이 빠듯하다.**

### iOS 위젯은 촬영용 고정을 따라오지 않는다

| | 날씨·시간대·시드 고정 |
|---|---|
| Android 앱 | 따라온다 |
| **Android 위젯** | **따라온다** (앱과 같은 프로세스. 매니페스트에 `android:process` 없음) |
| iOS 앱 | 따라온다 |
| **iOS 위젯** | **안 따라온다** (익스텐션은 별도 프로세스) |

**iOS 위젯이 들어가는 컷에서는 아무것도 고정하지 않는다.**
고정하면 iOS 앱과 iOS 위젯이 서로 다른 문장을 그려, 하필 "앱과 위젯이 어긋나지 않는다" 는
주장을 정면으로 깨는 그림이 나온다.

### 데스크톱은 앱이지 위젯이 아니다

`desktopApp` 이 있다 — Compose Multiplatform JVM 타깃(macOS/Windows/Linux).
`./gradlew :desktopApp:run` 으로 창 하나가 뜨고, 화면과 시작 절차는 모바일과 **같은 코드**다.
원래 콘티의 "Mac 데스크톱 위젯" 은 **위젯이 아니라 앱 창**으로 찍는다.

**데스크톱에는 결제가 없다** (`NoBilling` — 의도된 결정, docs/decisions/desktop-target.md).
상품이 비어 서가 진입점이 감춰지고, About 에 한 줄로만 안내한다.
그래서 **구매 컷(#8)은 데스크톱으로 찍을 수 없고**, 분할 화면에서도 데스크톱 쪽
푸터에는 `The shelf` 가 없다 — 클로즈업하지 말 것.

표면은 다섯이다: Android 앱(Compose) / Android 위젯(Glance) /
iOS 앱(Compose) / iOS 위젯(WidgetKit) / 데스크톱(Compose).

## 1. 촬영 전 준비

### 이것보다 먼저 할 일이 있다

**두 스토어 출시와 실제 구매 검증이 영상보다 앞선다.** Ship Kotlin Everywhere 는
iOS·Android 둘 다 필요하고, 구매가 안 되면 #8 을 찍을 수 없다.
심사위원 접근 경로는 docs/decisions/promo-code.md 참고.

### 빌드 두 개

| 빌드 | 쓰는 컷 | 이유 |
|---|---|---|
| **Release** | #1 #2 #3 **#4** #6 #8 #9 | 애니메이션이 최적화된 빌드. 역방향 넘김이 서명 컷이다 |
| **Debug** | #5 #7 | 촬영용 고정 메뉴가 여기에만 있다 |
| **데스크톱** | #7 | `./gradlew :desktopApp:run -Palmanac.demo=true` |

**#4 는 반드시 Release 로.** 고정이 필요 없는 컷이고(아카이브를 넘기기만 한다),
Kotlin/Native 디버그 바이너리는 최적화가 꺼져 있어 넘김이 무거워 보인다.
**#8(구매)도 Release 로** — 실제 스토어 결제 시트가 떠야 한다.

```bash
./gradlew :androidApp:assembleDebug
./gradlew :androidApp:assembleRelease     # 실키가 필요하다 (checkReleaseBillingKey)
```
iOS 는 Xcode 스킴의 Build Configuration 을 Debug / Release 로 바꿔 각각 실행한다.
데스크톱은 `-Palmanac.demo=true` 없이 띄우면 촬영 메뉴가 생기지 않는다.

### 촬영 메뉴

디버그 빌드(데스크톱은 `-Palmanac.demo=true`) → **About** → **Demo controls**.
릴리스에는 이 줄이 아예 없다.
날씨 8종 · 시간대 3종 · 기온(날씨에 딸려감) · 시드 · 아카이브 비우기.

**고정은 메모리에만 산다.** 앱을 다시 띄우면 전부 풀린다 — 고정된 줄 모르고 찍는 사고를
막으려고 일부러 그렇게 뒀다. 즉 **앱을 껐다 켜면 다시 고정해야 한다.**

### 기기 준비

- [ ] 위치를 **Seoul 로 수동 고정** (하단 도시 → Seoul). GPS 로 두면 좌표가 흔들려 슬롯이 갈린다
- [ ] 알림 끄기 / 방해금지 / 배터리 100% / 밝기 고정
- [ ] 홈 화면을 한 페이지로 정리하고 위젯만 남긴다 (#6)
- [ ] Android 위젯을 **가장 큰 크기**로 올려둔다
- [ ] **#8 용 기기는 구매하지 않은 상태로 남겨둔다.** 한 번 사면 되돌릴 수 없다 —
      #8 을 **가장 먼저** 찍거나, 별도 계정/기기를 쓸 것
- [ ] #5·#7 용 기기는 프로모션 코드로 전부 열어둔다 (얇은 칸에서 같은 문장이 반복되지 않게)

### 버킷 두께 (몽타주용)

전부 연 뒤 기준. **빈 칸은 없다** — 어떤 날씨를 고정해도 화면이 뜬다.

|  | morning | day | evening_night |
|---|---|---|---|
| clear | 49 | 88 | 68 |
| cloudy | 28 | 36 | 46 |
| fog | 30 | 31 | 34 |
| drizzle | **2** | 5 | 6 |
| rain | 24 | 39 | 45 |
| snow | 35 | 46 | 54 |
| thunder | **2** | 4 | 15 |
| wind | 50 | 68 | 89 |

`drizzle/morning` 과 `thunder/morning` 은 2편뿐이다. 이 둘을 쓸 거면
**시간대를 day 나 evening_night 으로** 두는 편이 안전하다.

## 2. 콘티

### #1 콜드 오픈 · 0:00–0:07
**화면** 검은 화면 → 하늘 그라데이션이 위에서 채워짐 → `N years ago` 가 크게 →
발췌문 → 작가·작품·연도
**자막** `This weather, written {N} years ago.`
**촬영** Release. 고정 없음
**비고** 로고도 인트로도 없다. 자막의 `{N}` 은 그날 찍힌 실제 숫자로 맞출 것

### #2 이게 무슨 앱인가 · 0:07–0:14
**화면** 화면이 오늘 페이지 전체로 물러나며 상단 날씨 줄(`someone watched this rain · 14°`)과
도시 이름이 함께 보인다. 앱 이름을 짧게 얹는다
**자막** `Almanac matches today's sky with literature.`
**비고** **이 컷이 새로 들어간 것이다.** 사전 심사는 첫 2분에서 앱 설명과 참가 부문을 본다.
감성만으로 14초를 넘기면 "무슨 앱인지" 가 늦는다

### #3 매칭 원리 · 0:14–0:26
**화면** 날씨 칩 → 발췌문 속 날씨 단어가 은은하게 강조 (편집에서)
**자막** `Weather chooses today's page.`
**촬영** Release. 실제 비가 오면 그대로. 아니면 Debug 로 rain 고정
**비고** 선별 기준(날씨 단어 필수)이 화면에서 증명되는 장면

### #4 시그니처 · 역방향 책장 넘김 · 0:26–0:38
**화면** 스와이프 → 책장이 **과거 쪽으로** 넘어감 → 연도 카운터가 올라감. 2회 반복
**자막** `Turn back through time.`
**촬영** **Release 필수.** 고정 없음. 아카이브에 최소 5장
**비고** 디자인 심사의 핵심 컷. 왼쪽 가장자리를 축으로 들리는 동작이 보이게 측면광을 쓸 것

> 아카이브를 쌓는 법: 촬영 며칠 전부터 아침·낮·저녁에 한 번씩 연다.
> Debug 로 시간대를 바꿔가며 열어도 쌓이지만 그렇게 쌓은 기록은 **오늘 날짜에 몰린다.**
> 넘길 때 날짜가 전부 같으면 "과거로 되돌아간다" 는 느낌이 죽는다.

### #5 하늘의 변주 · 0:38–0:53
**화면** 같은 구도로 rain / snow / fog / wind 를 3~4초씩 → 이어서 같은 날씨로
morning / day / evening_night 을 2초씩
**자막** `Each sky reveals a different page.` + 구석에 라벨(`Rain` … `Dawn → Dusk`)
**촬영** Debug. 앞쪽은 날씨만, 뒤쪽은 **시간대만** 바꾼다
**비고** **이 컷의 주인공은 문장이 아니라 등장 애니메이션이다.** 날씨를 바꾸는 순간
단어들이 그 날씨처럼 움직인다(비는 떨어지고 안개는 초점이 맞는다) — 정지 화면으로는
안 보이는 것이라 디자인 심사가 볼 것이 정확히 여기다.

컷을 애니메이션보다 짧게 자르지 말 것. **눈이 2.3초로 가장 길다** — 이 컷만 4초를 준다.
뒤쪽에서 날씨까지 같이 바뀌면 무엇이 문장을 갈랐는지 안 보인다.
크로스 디졸브 없이 컷으로 붙이는 편이 대비가 산다

### #6 생활 속 사용 · 위젯 · 0:53–1:08

**위젯을 눌러 앱으로 들어가 같은 문장이 열리는 것까지**
**자막** 없음 (화면이 스스로 설명한다)

Android 위젯은 히어로만 커스텀 폰트 비트맵이고 본문은 시스템 serif 다 — 클로즈업 주의

### #7 KMP 증명 · 1:08–1:26
**화면**
1. Android | iPhone | 데스크톱 창 **3분할**. 같은 제스처(역방향 넘김)를 동시에 하고
   **같은 문장에 도착한다** — 12초
2. 구조 카드 6초

```text
Shared Kotlin
weather · matching · SQLDelight

Android              iOS                  Desktop
Compose · Glance     Compose · WidgetKit  Compose
```

**자막** `One Kotlin core. Native everywhere.`
**촬영** Debug 두 기기 + `-Palmanac.demo=true` 로 띄운 데스크톱. 순서가 중요하다 ↓
**비고** **정지 화면 세 장으로는 부족하다.** 같은 입력에 같은 반응이 나오는 것을 보여야
"같은 코어" 가 읽힌다. `deterministic pick` 은 카드에서 뺐다 — 기술적이라 6초 안에 안 읽힌다.
그 설명은 Devpost 본문으로 옮긴다.

데스크톱 창은 폰 비율(440×860)이라 3분할에 그대로 들어간다.
다만 **데스크톱 푸터에는 `The shelf` 가 없다**(결제 없음) — 푸터를 클로즈업하지 말 것

> **세 화면을 맞추는 순서** (이 순서여야 한다)
> 1. 셋 다 위치를 Seoul 로 고정
> 2. Demo controls → Seed → **Shared seed**
> 3. Demo controls → **Clear the archive** ← 빠뜨리면 안 맞는다
> 4. Demo controls → 날씨와 시간대를 **같은 값**으로 고정
> 5. 셋에서 같은 방향으로 몇 장 넘겨 아카이브를 같은 모양으로 만든다
>
> 3번이 필요한 이유: 슬롯은 한 번 고정되면 시드를 바꿔도 다시 고르지 않는다.
> 읽음 횟수와 히스토리도 선택의 입력이라(결정론 계약 2.7) 출발선을 맞춰야 한다.
>
> **Demo 화면은 절대 프레임에 들어가면 안 된다.**

### #8 구매 · RevenueCat 증명 · 1:26–1:38
**화면** (12초)
1. 서가 화면 — `A starter shelf … you will start meeting the same passages again.`
   + `Buy · ₩5,500` 버튼 (3초)
2. 버튼 탭 → **실제 스토어 결제 시트**. 가격과 `One time. Not a subscription.` (4초)
3. 구매 완료 → **앱이 확인 화면으로 바뀐다** (5초)
   — `The shelf is open` / `342 passages are yours now — every weather, every hour of the day.`
**자막** `One purchase opens the whole shelf.`
