# 데모 영상 — 콘티와 촬영 준비

2026-09-25. Shipaton 제출용. 목표 길이 **1분 45초** (상한 2분에서 15초 여유).
외부 피드백 2차 반영본.

대사(내레이션)는 넣지 않는다. **영어 자막 8줄뿐이다.**
심사위원이 무음으로 볼 가능성이 높고, 대사가 적을수록 타이포그래피가 화면을 쥔다.

**심사 영상이지 브랜드 필름이 아니다.** 감성 훅으로 열되,
*무엇을 하는 앱인지*는 **14초 안에** 끝내고, KMP 와 결제 증명에 뒤 40초를 쓴다.

## 0. 먼저 알아야 할 제약

코드에서 확인한 것들이다. 넷 다 **콘티를 바꾼다.**

### 일본어 화면은 지금 찍을 수 없다

- `content.db` 의 엔트리는 **428편 전부 영어**다. 일본어는 0편이다
  (`SELECT language, COUNT(*) FROM entries GROUP BY language` → `('en', 428)`)
- 앱에 언어 선택이 없다. `AlmanacService.pages(language = "en")` 이 기본값 그대로 쓰인다.
  UI 문자열도 App.kt 에 영어로 박혀 있다

로컬라이제이션 컷은 **뺐다.** 찍으려면 아오조라 큐레이션 + 언어 선택 UI 가 먼저다.
남는 8초는 위젯 컷과 구매 컷에 돌린다.

> 같은 이유로 About 화면의 *"Japanese passages come from Aozora Bunko"* 는
> 지금 앱이 뒷받침하지 못하는 문장이다. 출처 **정책**을 적은 것이라 거짓은 아니지만,
> 심사위원이 찾아보면 안 나온다. 영상과 별개로 손볼지 결정할 것.

### 위젯도 아카이브도 유료가 아니다

**파는 것은 기능이 아니라 서가의 크기다.** 무료 유저도 위젯과 아카이브를 포함해
앱 전체를 쓴다. 다만 문장이 86편이라 같은 것을 다시 만나게 된다 (전체는 428편).

그래서 `Unlock widgets and the archive` 같은 자막은 **사실이 아니고**,
"잠긴 아카이브 → 해제" 그림도 만들 수 없다. 구매 컷은 아래 #8 처럼 짠다.

### 구매해도 지금 보고 있는 문장은 바뀌지 않는다

슬롯은 (날짜, 시간대, 위치)로 한 번 고정되면 보유 팩이 늘어도 다시 고르지 않는다
(결정론 계약 2.5 — 표시 안정성이 우선이다). **"구매 → 화면의 문장이 바뀐다" 는 못 찍는다.**

대신 구매 직후 **확인 화면**이 뜬다 — `The shelf is open` / `342 more passages are yours now`.
구매 컷의 증거는 이쪽이다. 페이지로 돌아온 뒤에는 서가 진입점이 사라진 것만 남는다.

### 문장 등장 애니메이션이 있다 — 이게 몽타주의 주인공이다

`WeatherEntrance.kt` 가 **문장 자체를 날씨처럼 움직인다.** 배경 파티클이 아니라 단어가
움직이는 것이라, 정지 스크린샷으로는 안 보이고 영상으로만 보인다 — 디자인 심사가 볼 것이 이것이다.

| 날씨 | 단어의 행동 | 길이 |
|---|---|---|
| 맑음 | 살짝 떠올라 놓인다 | 850ms |
| 흐림 | 거의 안 움직이고 천천히 배어 나온다 | 1500ms |
| 안개 | 흐림에서 한 덩어리로 초점이 맞는다 | 1700ms |
| 이슬비 | 작은 낙하, 조금 흩어진 순서 | 950ms |
| 비 | 가속하며 떨어져 바닥에서 멈춘다 | 1150ms |
| 눈 | 천천히 내려앉으며 좌우로 흔들린다. **가장 느리다** | 2300ms |
| 뇌우 | 종이가 두 번 번쩍인 뒤 세 무리가 툭 놓인다 | 950ms |
| 바람 | 왼쪽에서 불려 와 지나쳤다가 제자리 | 1050ms |

**촬영 메뉴에서 날씨를 바꾸면 등장이 다시 재생된다** (등장의 키에 날씨 그룹이 들어 있다).
몽타주는 이걸 그대로 쓰면 된다 — 컷마다 날씨를 바꾸는 것이 곧 애니메이션 재생이다.

컷 길이를 애니메이션보다 짧게 잡으면 안 된다. **눈은 2.3초짜리라 3초 컷이 빠듯하다.**

### iOS 위젯은 촬영용 고정을 따라오지 않는다

| | 날씨·시간대·시드 고정 |
|---|---|
| Android 앱 | 따라온다 |
| **Android 위젯** | **따라온다** (앱과 같은 프로세스. 매니페스트에 `android:process` 없음) |
| iOS 앱 | 따라온다 |
| **iOS 위젯** | **안 따라온다** (익스텐션은 별도 프로세스) |

**iOS 위젯이 들어가는 컷에서는 아무것도 고정하지 않는다.**
고정하면 iOS 앱과 iOS 위젯이 서로 다른 문장을 그려, 하필 "앱과 위젯이 어긋나지 않는다" 는
주장을 정면으로 깨는 그림이 나온다.

### 데스크톱은 앱이지 위젯이 아니다

`desktopApp` 이 있다 — Compose Multiplatform JVM 타깃(macOS/Windows/Linux).
`./gradlew :desktopApp:run` 으로 창 하나가 뜨고, 화면과 시작 절차는 모바일과 **같은 코드**다.
원래 콘티의 "Mac 데스크톱 위젯" 은 **위젯이 아니라 앱 창**으로 찍는다.

**데스크톱에는 결제가 없다** (`NoBilling` — 의도된 결정, docs/decisions/desktop-target.md).
상품이 비어 서가 진입점이 감춰지고, About 에 한 줄로만 안내한다.
그래서 **구매 컷(#8)은 데스크톱으로 찍을 수 없고**, 분할 화면에서도 데스크톱 쪽
푸터에는 `The shelf` 가 없다 — 클로즈업하지 말 것.

표면은 다섯이다: Android 앱(Compose) / Android 위젯(Glance) /
iOS 앱(Compose) / iOS 위젯(WidgetKit) / 데스크톱(Compose).

## 1. 촬영 전 준비

### 이것보다 먼저 할 일이 있다

**두 스토어 출시와 실제 구매 검증이 영상보다 앞선다.** Ship Kotlin Everywhere 는
iOS·Android 둘 다 필요하고, 구매가 안 되면 #8 을 찍을 수 없다.
심사위원 접근 경로는 docs/decisions/promo-code.md 참고.

### 빌드 두 개

| 빌드 | 쓰는 컷 | 무엇인가 |
|---|---|---|
| **demo** | **#1–#7** | release 최적화 + 촬영 메뉴. 촬영의 기본 빌드다 |
| **스토어 빌드** | **#8** | 테스트 트랙에서 설치한 것. 결제가 실제로 도는 유일한 환경 |

**Debug 로는 찍지 않는다.** 예전 계획은 #5 와 #7 을 Debug 로 잡고 있었는데,
그러면 디자인 심사의 핵심(등장 애니메이션)과 KMP 증명(3기기 넘김)이 가장 느린
빌드로 찍힌다. 촬영 메뉴가 Debug 에만 있었기 때문이었고, 그래서 빌드를 하나 더 만들었다.

```bash
./gradlew :androidApp:assembleDemo                 # Android 촬영 빌드
./gradlew :desktopApp:run -Palmanac.demo=true      # 데스크톱
```
iOS 는 Xcode 스킴의 Build Configuration 을 **DemoRelease** 로 바꿔 실행한다.

### #8 은 테스트 트랙에서 설치한 빌드로 찍는다

**`assembleRelease` APK 를 사이드로드하는 것으로는 안 된다.** Play Billing 은
Play 가 설치한 앱에서만 동작한다 — 내부 테스트 트랙에 올리고 라이선스 테스터 계정으로
설치해야 결제 시트가 뜬다. iOS 는 TestFlight(샌드박스) 또는 스토어 빌드다.

### 촬영 순서가 정해진다

demo 빌드와 스토어 빌드는 **서명이 달라 같은 기기에 겹쳐 설치되지 않는다.**
전환하려면 지워야 하고, 지우면 아카이브(#4 가 쓰는 것)가 날아간다.

> **#1–#7 을 demo 빌드로 먼저 전부 찍고, 그다음 지우고 스토어 빌드로 #8 을 찍는다.**
> #8 은 구매 이력이 없는 계정이어야 하므로 어차피 깨끗한 상태가 낫다.

### 촬영 메뉴

demo 빌드(iOS 는 DemoRelease, 데스크톱은 `-Palmanac.demo=true`) →
**About** → **Demo controls**. 스토어로 나가는 릴리스에는 이 줄이 아예 없다.
날씨 8종 · 시간대 3종 · 기온(날씨에 딸려감) · 시드 · 아카이브 비우기.

**고정은 메모리에만 산다.** 앱을 다시 띄우면 전부 풀린다 — 고정된 줄 모르고 찍는 사고를
막으려고 일부러 그렇게 뒀다. 즉 **앱을 껐다 켜면 다시 고정해야 한다.**

### 기기 준비

- [ ] 위치를 **Seoul 로 수동 고정** (하단 도시 → Seoul). GPS 로 두면 좌표가 흔들려 슬롯이 갈린다
- [ ] 알림 끄기 / 방해금지 / 배터리 100% / 밝기 고정
- [ ] 홈 화면을 한 페이지로 정리하고 위젯만 남긴다 (#6)
- [ ] Android 위젯을 **가장 큰 크기**로 올려둔다
- [ ] #1–#7 용 기기는 프로모션 코드로 전부 열어둔다 (얇은 칸에서 같은 문장이 반복되지 않게)
- [ ] **#8 용 계정은 구매 이력이 없어야 한다.** 다만 되돌릴 수 없는 것은 아니다 —
      TestFlight 샌드박스 구매는 지울 수 있고 Play 테스트 구매는 환불·취소가 된다.
      **그 경로를 촬영 전에 한 번 확인해 둘 것** (실패하고 나서 찾으면 늦다)

### 버킷 두께 (몽타주용)

전부 연 뒤 기준. **빈 칸은 없다** — 어떤 날씨를 고정해도 화면이 뜬다.

|  | morning | day | evening_night |
|---|---|---|---|
| clear | 49 | 88 | 68 |
| cloudy | 28 | 36 | 46 |
| fog | 30 | 31 | 34 |
| drizzle | **2** | 5 | 6 |

## 1.5 촬영 자동화

컷 하나가 명령 한 줄이다. 마음에 안 드는 컷은 그 컷만 다시 돌리면 되고 결과는 매번 같다.

```bash
export ALMANAC_DEVICE=<adb 기기>                            # Android
python3 scripts/record_demo.py montage <녹화 디렉터리>      # #5 일곱 컷

python3 scripts/ios_record.py cold  <출력.mp4> [초]         # iOS — 찬 시작
python3 scripts/ios_record.py hold  <출력.mp4> [초]         # iOS — 지금 화면
python3 scripts/ios_record.py start <출력.mp4>              # iOS — 조작하며 녹화
python3 scripts/ios_record.py stop

python3 scripts/cut_demo.py cut <컷 이름> <녹화 뿌리> <컷 디렉터리>
python3 scripts/cut_demo.py montage <녹화> <출력.mp4>       # 정확히 15.00초로 조립
python3 scripts/cut_demo.py subtitles <출력 디렉터리>       # 자막 8장
python3 scripts/cut_demo.py status <컷 디렉터리>            # 어디까지 찍었나
python3 scripts/cut_demo.py preview <컷 디렉터리> <출력>    # 찍은 것만 이어보기
python3 scripts/cut_demo.py master <컷 디렉터리> <출력>     # 전체 이어붙이기
swift scripts/render_card.swift <폰트> <출력.png>           # #7 구조 카드
```

컷마다 **원본의 어디서부터 쓰는지**는 `cut_demo.py` 의 `SOURCES` 에 적혀 있다.
자막과 카메라 움직임도 거기서 자동으로 붙으므로 `cut` 한 번이 완성된 한 컷이다.

`master` 는 **2분을 넘기면 만들지 않는다.** 상한이 대회 규정이므로 사람이 기억할 일이 아니다.

### iOS 는 조작과 녹화를 나눈다

`simctl` 에는 탭이 없다. 그래서 `ios_record.py` 는 **녹화와 앱 수명만** 맡고
화면을 누르는 일은 바깥(시뮬레이터 제어 도구)에서 한다. 그 경계 덕분에 컷은
여전히 결정적이다 — 녹화의 시작·종료는 `simctl` 이 쥐고, 탭은 녹화 앞이나
`start`/`stop` 사이에서만 일어난다.

**두 기기를 한 영상에 섞는다.** 시스템 영역을 걷어내면 남는 것은 앱 화면뿐이라
Galaxy 와 iPhone 이 나란히 붙어도 티가 안 난다. 크롭 값은 녹화 해상도로 고른다
(`DEVICE_CROP`) — 파일이 스스로 어느 기기에서 왔는지 말한다.

### 찍고 나서 발견한 것 — 촬영일에 정할 것 둘

**1. 지금까지 찍은 컷은 전부 "안 산 상태" 다.** 푸터에 `The shelf` 가 있다
(#1–#5, #6 iPhone 절반, #9). 그런데 #7 을 전부 열어둔 기기로 찍으면 그 줄이 사라진다.
콘티 순서가 #7 → #8 이므로, **서가 진입점이 그걸 없애는 구매보다 먼저 사라진다** —
앞뒤가 맞지 않는다.

> **#7 도 잠긴 상태로 찍는 편이 낫다.** 영상 전체가 "아직 안 산 사람" 의 화면이고
> #8 이 그걸 여는 사건이 된다. 대신 세 화면의 보유 팩이 같아야 하므로
> **Android 는 지우고 다시 설치해야 한다** (코드로 연 것을 UI 로 되돌릴 수 없다).
> iOS·데스크톱은 `owned_packs` 에서 `core-2026` 줄을 빼면 된다.

**2. #5 에 같은 책이 두 번 나온다.** 일곱 컷의 출처는 이렇다.

| 컷 | 책 |
|---|---|
| Rain | **Sons and Lovers, 1913 · D. H. Lawrence** |
| Snow | Anne of Green Gables, 1908 · L. M. Montgomery |
| Fog | Great Expectations, 1861 · Charles Dickens |
| Wind | Far from the Madding Crowd, 1874 · Thomas Hardy |
| Dawn | The Wind in the Willows, 1908 · Kenneth Grahame |
| Day | My Antonia, 1918 · Willa Cather |
| Dusk | **Sons and Lovers, 1913 · D. H. Lawrence** |

문장은 서로 다르지만 15초 안에 같은 제목이 두 번 스친다. 얇은 서가(86편)로 찍어서다.
`TIME_CUT_WEATHER` 를 `Clear` 말고 다른 빠른 날씨(drizzle 950ms · thunder 950ms)로
바꿔 시간대 세 컷만 다시 찍으면 갈릴 가능성이 높다.

**#7 을 고를 때도 이 표를 피할 것.** 여기 있는 책이 또 나오면 서가가 얇아 보인다.

### 데스크톱 녹화에는 권한이 하나 필요하다

`screencapture -v` 가 막혀 있다 (정지 캡처는 된다). 시스템 설정 → 개인정보 보호 및
보안 → **화면 기록** 에서 터미널/Claude Code 를 켜야 창을 녹화할 수 있다.
안 되면 데스크톱 2초만 직접 녹화해서 넘겨줄 것.

### 찍으면서 알게 된 것

- **녹화가 도는 동안 화면을 조회하면 안 된다.** 접근성 덤프 한 번이 1~2초라 그만큼
  촬영 메뉴가 찍힌다. 처음 시도에서 7컷 중 5컷이 메뉴 화면이었다.
  좌표를 미리 구해두고 녹화 중에는 누르기만 한다
- **`screenrecord` 는 화면이 바뀔 때만 프레임을 쓴다.** 정지 구간이 파일에서 사라지므로
  파일 안의 시각은 벽시계와 다르고, 문장이 다 놓인 뒤의 정적은 편집에서 만들어야 한다
- **화면 맨 아래 요소를 그냥 누르면 탭이 시스템 내비게이션 바로 간다.**
  About 의 `Demo controls` 가 정확히 그 자리다

## 4. 녹화·편집

- **60fps.** 역방향 넘김이 서명 컷이라 30fps 로 찍으면 거기서 티가 난다
- 기기 네이티브 녹화 — Android `adb shell screenrecord --bit-rate 16000000`,
  iOS 제어 센터 녹화
- 분할 화면은 **각 녹화를 편집에서 동기화**한다 (#7 은 폰 둘 + 데스크톱 하나)
- **햅틱은 영상에 안 찍힌다.** 날씨별 햅틱이 등장 애니메이션과 **같은 타임라인**으로
  들어가 있는데(단어가 놓이는 프레임에 진동한다) 화면에는 아무것도 남지 않는다.
